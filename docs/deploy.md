# Деплой на Vercel

1. Импортируйте репозиторий в Vercel — настройки сборки подтянутся из [`vercel.json`](../vercel.json).
2. **Storage → Create Database → Neon (Postgres)** и подключите базу к проекту — Vercel сам добавит `DATABASE_URL`.
   Таблицы создаются автоматически при первом запросе.
3. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
4. **Settings → Environment Variables**:
   - `ADMIN_PASSWORD` — длинный случайный пароль (не короче 12 символов);
   - `TELEGRAM_BOT_TOKEN` — токен бота.
5. **Redeploy** → откройте `/admin` → блок «Telegram и защита» → **Подключить** (вебхук бота).
6. Нажмите у бота **Start** и отправьте `/id` — бот ответит вашим Telegram ID.
   Добавьте его в `TELEGRAM_ADMIN_IDS` (несколько админов — через запятую, без пробелов) и снова сделайте **Redeploy**.
   Теперь для входа в админку нужен ещё и код, который бот присылает в Telegram.

> Если доступ к админке потерян — удалите `TELEGRAM_ADMIN_IDS` и сделайте Redeploy: вход вернётся к одному паролю.

## Почему не SQLite

На Vercel код работает в serverless-функциях без постоянного диска — файл базы терялся бы
между запросами. Поэтому в продакшене используется Neon Postgres, а локально — PGlite
(тот же Postgres, встроенный в процесс), чтобы SQL был одинаковым.

## Проверка бота локально

Telegram не может достучаться до `localhost`, поэтому локально сервер сам забирает сообщения
(long polling). Создайте **отдельного тестового бота** — polling отключает вебхук того бота,
чей токен указан:

```bash
TELEGRAM_BOT_TOKEN=<токен тестового бота>
TELEGRAM_POLLING=1
```
